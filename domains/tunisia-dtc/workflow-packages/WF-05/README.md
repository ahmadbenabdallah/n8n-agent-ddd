# Tunisia DTC Agent System FINAL v4 — WF-05 Sales Engine

## Scope
Production update for **WF-05 Sales Engine** only.

WF-05 is the deterministic sales-orchestration layer that converts the routed customer intent and trusted conversation context into a bounded conversational sales plan. It does **not** authorize or execute commerce mutations.

Core architecture remains:

> LLM proposes → n8n validates/authorizes → commerce executes → n8n verifies → renderer replies.

WF-05 coordinates:
- discovery
- product consideration and comparison
- objections
- product selection
- cart-building intent
- checkout readiness
- post-purchase sales context

It delegates commerce operations to:
- WF-11 Product Service
- WF-12 Cart Service
- WF-13 Promotion Service
- WF-14 Checkout Service
- WF-07 Order Service where order context is relevant
- WF-08 Escalation when human ownership is required

WF-10 remains the sole hard authorization boundary.
WF-20 remains the sole privileged WooCommerce boundary.

## v4 changes
1. Sales state is deterministic and persisted through WF-03.
2. Customer identity context from WF-02/WF-03 is consumed but never promoted by WF-05.
3. Human ownership from v4 is a control signal: WF-05 cannot perform conflicting automation while `conversation_owner=HUMAN` or `automation_mode=PAUSED`.
4. Product/price/stock facts are obtained through authoritative services, not inferred by the LLM.
5. Cart, promotion and checkout operations are delegated to their dedicated workflows.
6. Checkout readiness requires fresh validation; stale conversational facts cannot authorize purchase.
7. Every consequential proposal carries an action ID/idempotency key and is revalidated by WF-10.
8. Customer-facing operational acknowledgements are generated by controlled renderer/acknowledgement logic, not invented by the LLM.
9. Sales logic never fabricates scarcity, urgency, social proof, discounts, guarantees or competitor claims.
10. All sales transitions are allowlisted.

## Non-goals
WF-05 does not:
- call WooCommerce directly
- grant permissions
- verify customer identity
- create orders
- mark payment as paid
- construct checkout URLs
- expose private order data
- override promotion eligibility
- override inventory or pricing
