# n8n Integration Runbook

## 1. Create the n8n environment

Create separate DEV, STAGING and PROD n8n environments.

Configure:

- base URL
- HTTPS
- PostgreSQL
- encryption key
- timezone
- execution retention
- error workflow
- user access
- project/folder structure.


## 4. After every import

Do not immediately activate.

For each workflow:

```text
Import
→ open
→ inspect every node
→ inspect expressions
→ inspect credentials
→ inspect URLs
→ inspect environment references
→ inspect Execute Workflow references
→ inspect error branches
→ save
→ execute with fixture
→ verify output
```

## 5. Execute Workflow references

All child workflow calls must reference the actual production/staging workflow IDs or stable workflow selection mechanism.

Do not assume imported workflow IDs match the original environment.

After import, make a dependency table:

```text
caller → child workflow → environment
```

Resolve every reference before activation.

## 6. Credentials

Attach environment-specific credentials.

Never copy a production credential into DEV.

## 7. External HTTP nodes

For every HTTP Request node record:

```text
method
URL
authentication
headers
timeout
retry
request schema
response schema
error handling
idempotency
```

Do not accept a URL generated by the LLM.

## 8. Retry policy

Retry:

- network timeout
- temporary 429
- transient 5xx

Do not retry automatically:

- authorization denial
- schema validation failure
- policy denial
- identity failure
- prompt injection
- invalid parameters.

## 9. Timeouts

Set explicit timeouts for:

- OpenAI
- Supabase
- Meta
- commerce
- payment
- helpdesk.

Do not let a webhook execution hang indefinitely.

## 10. Error workflow

Every workflow should route unexpected failures to the central error/dead-letter workflow.

The error workflow should:

- capture execution/correlation ID
- classify error
- redact secrets
- persist event
- alert according to severity
- avoid leaking raw error to customers.

## 11. Activation rule

A workflow is activated only after:

```text
import test PASS
contract test PASS
failure test PASS
security test PASS where applicable
dependency mapping PASS
```

# 12. Parent/child pattern

Keep the channel-facing parent thin.

Parent:

```text
Webhook
→ normalization
→ invoke security
→ invoke identity
→ invoke state
→ invoke intent
→ invoke business service
→ invoke reasoning
→ invoke authorization
→ invoke commerce
→ render
→ send
```

Child workflows should return normalized contracts.

Example:

```json
{
  "ok": true,
  "error_code": null,
  "retryable": false,
  "data": {}
}
```

Failure:

```json
{
  "ok": false,
  "error_code": "UPSTREAM_TIMEOUT",
  "retryable": true,
  "data": null
}
```

Do not pass provider-specific error objects through the entire system.

# 13. n8n expression safety

Do not interpolate untrusted customer text into:

- system instructions
- SQL
- URLs
- authorization headers
- executable code.

Customer data must remain data.

For SQL, use parameterized queries or safe database nodes.

For external URLs, use allowlisted static base URLs.

For action parameters, validate against schemas before execution.

---

# 14. Production n8n security

At minimum:

- strong admin authentication
- least-privilege users
- restricted project access
- protected credentials
- HTTPS
- no exposed internal webhook endpoints without authentication
- backups
- controlled environment variables
- execution-data retention
- audit of administrative changes
- restricted outbound network where practical.

Review the actual n8n deployment configuration before production.
