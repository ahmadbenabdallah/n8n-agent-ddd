# Support

## Start with the documentation

Use the public documentation for:

- installation
- configuration
- development
- domain packs
- deployment
- operations
- troubleshooting

## Bug reports

For reproducible bugs, open a GitHub issue using the project's issue templates.

Include:

- version/commit
- environment
- relevant configuration without secrets
- reproduction steps
- expected behavior
- actual behavior
- logs with secrets and personal data removed

## Feature requests

Explain:

- the problem
- who is affected
- proposed behavior
- alternatives considered
- whether the request changes a platform contract or domain boundary

## Security

Do not use public issues for vulnerabilities. Follow `SECURITY.md`.

## Support expectations

This is an open-source project under active development. Response times are not guaranteed unless a separate support agreement is provided.
