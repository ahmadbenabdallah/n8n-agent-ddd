## The failure

`tests/documentation/phase20.3-contract.sh` exited 127: `scripts/docs/validate-public-docs.sh` did not exist in the clone.

Root cause, confirmed by `git check-ignore`:

```
$ git check-ignore -v scripts/docs/validate-public-docs.sh
.gitignore:10:docs/	scripts/docs/validate-public-docs.sh

$ git ls-files scripts/docs
(no output)
```

`.gitignore` line 10 was `docs/` with no leading slash. A gitignore pattern containing no slash except a trailing one matches a directory of that name **at any depth**, so it excluded every nested `docs/` folder in the repository, not just the internal `/docs/` tree it was written for. Before the fix, `git ls-files | grep -c '/docs/'` returned **0**.

Two things were silently uncommitted:

1. `scripts/docs/validate-public-docs.sh`, which a test executes. The suite could never pass for anyone who cloned.
2. 195 files across 27 `docs/` folders under `domains/tunisia-dtc/source-material/expanded-archives/`, while the rest of each archive stayed tracked, leaving the source material half-committed.

Fixed in `182c963` by anchoring the rule to `/docs/` and committing the 196 files. Verified in both directions: the script is no longer ignored, and `docs/roadmap/VALIDATION-ROADMAP.md` still is. `pnpm test` is now 40 passed, 0 failed, 3 skipped.

A second defect surfaced immediately afterwards and is recorded under A4: the newly committed script went in as mode 644, which would fail on Linux.

## Follow-up

1. A lint for unanchored `.gitignore` directory patterns would have caught this in seconds. Candidate for group K.
2. Every test that depends on a file's presence should assert it is tracked, not merely present on disk. `phase20.3-contract.sh` checks `-f`, which is true on the dev machine whether or not the file is committed. This class of test passes locally and fails for everyone else.
3. A3 should be re-run from a clean clone whenever `.gitignore` changes.
