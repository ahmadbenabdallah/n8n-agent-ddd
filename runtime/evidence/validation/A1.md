# A1 Node 22 on every machine

Status: PASS (with one defect found)
Date: 2026-09-19
Environment: Windows 11, Git Bash, fnm

## Commands

```bash
fnm install 22                                   # installed v22.23.2
N22="$HOME/AppData/Roaming/fnm/node-versions/v22.23.2/installation"
export PATH="$N22:$PATH"
"$N22/corepack" pnpm --version                   # 10.15.0, from the packageManager pin
"$N22/corepack" pnpm install --frozen-lockfile   # no engine-strict override
"$N22/corepack" pnpm run doctor|validate|build|test
```

The repository installs and passes every check on Node 22 with no override. Earlier work needed `npm_config_engine_strict=false` only because this machine was on Node 23.

## Defect found: `pnpm doctor` never runs the project's doctor

`doctor` is a **built-in pnpm command**, so `pnpm doctor` runs pnpm's own checker, prints nothing here, and exits 0. The project's `scripts/doctor.ts` is never executed. Only `pnpm run doctor` works.

Six places documented the wrong form: `README.md` (3), `documentation/getting-started/README.md`, `documentation/installation/index.md` and `.github/pull_request_template.md`. All corrected to `pnpm run doctor`.

This also means every earlier "doctor passed" claim in this project's history proves nothing.

## Environment notes

- `fnm exec --using=22 -- pnpm` does not work here: the multishell path does not carry pnpm or corepack. Use the installation directory directly, as above.
- corepack 0.34.6 ships with Node 22 and resolves the pinned pnpm 10.15.0 without a global install.

## Follow-up

1. `.nvmrc` added with `22`, so `fnm use` and `nvm use` pick the right version automatically.
2. Decision for the owner: `engines` is `>=22 <23`, and with `engine-strict=true` that blocks anyone on Node 24. Recommend widening to `>=22` once the test suite runs on 24 in CI.
3. Check the other package scripts for the same shadowing problem (pnpm built-ins include `install`, `add`, `test`, `publish`, `audit`, `config`, `doctor`). Belongs to task B1.
