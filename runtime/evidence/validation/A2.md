The server is reachable and the active context is `desktop-linux`, so Linux containers run natively through the WSL2 backend. Compose v5 is the plugin form (`docker compose`), not the legacy `docker-compose` binary; every script in this repository already uses the plugin form.

## Scope note

A2 asks only whether Docker is reachable. It does **not** prove that this repository's compose stacks build, start, migrate or serve; that is group E and group G. An earlier attempt to pull the `pgvector` and n8n images as part of A2 was out of scope and was stopped. The only fact it produced, recorded here because it cost nothing: both image tags referenced by the compose files resolve in the registry.

## Follow-up

1. Engine is `Experimental: true` on this machine. Nothing in the repository depends on experimental features today; worth re-checking if any script starts using one, because CI runners will not have it.
2. Compose v5 is well ahead of the v2 syntax most of the repository's compose files were written against. Group G should confirm the files still parse under v5 (`docker compose config`) before relying on them.
