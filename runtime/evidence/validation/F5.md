The contract half passes, and passes for reasons that have nothing to do with
Codex. `AGENTS.md` at the repository root is the cross-tool standard, read by
Codex, Cursor, Copilot, Gemini and Zed alike. `.codex/AGENTS.md` adds one
sentence redirecting to it, and `scripts/validate-agents.ts` checks the file
exists and that the root contract still names `workflow_roles`,
`privileged_external_execution`, `authorization`, production access and runtime
secrets. That is the part of F5 worth keeping.

## Defect: the role files carry nothing

All seven are two lines:

```toml
name = "architect"
description = "n8n-agent-ddd architect role"
```

`.codex/roles/{architect,chief,developer,pm,qa,reviewer,security}.toml` restate
the names already listed in `agent-manifest.yaml` under `agents.roles`, and say
nothing about what any role may do. They do not load a policy, bound a
permission, or reference `.agents/policies/`. An adopter who reads them learns
the project has seven roles, which `agent-manifest.yaml` already told them.

They are worse than empty: they present as configuration, so the next person
grows them, and the contract quietly forks between `AGENTS.md` and seven TOML
files that no validator reads.

**Recommendation: delete `.codex/roles/*.toml`.** Keep `.codex/AGENTS.md`,
which `validate-agents.ts` requires, and let `AGENTS.md` plus
`.agents/policies/` carry the contract for every tool. Nothing reads the role
files, so deletion is safe; `agents.roles` in `agent-manifest.yaml` remains the
list of roles.

**Deferred, not done.** NAD-004 caps a change at 15 files and the seven
deletions would take it to 22. The plugin and its test took the budget. This is
a one-commit follow-up with no dependencies.

## Why there is no Codex plugin

F4 ships a Claude Code plugin; F5 ships nothing equivalent, deliberately.
Claude Code has a plugin format with commands, skills and a marketplace, so
there is something to install. Codex has `AGENTS.md`, which this repository
already serves, and the domain-builder's real work is a plain Node script
(`plugins/domain-builder/scripts/scaffold-domain.mjs`, zero dependencies) that
any agent or human can run directly:

```bash
node plugins/domain-builder/scripts/scaffold-domain.mjs --help
```

A Codex adapter would be a second copy of the same three prompts pointing at
the same script. The decision recorded here is to keep one script and one
contract rather than one per tool.
